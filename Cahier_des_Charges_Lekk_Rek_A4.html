Vision Produit & Spécifications

La vision : Lekk Rek devient la plateforme web centralisée de commande de repas au quotidien. La plateforme gère la découverte, la commande en ligne, le paiement intégré, et le suivi de bout en bout. Le porteur de projet a une mainmise totale sur l'écosystème : les restaurants n'interagissent pas avec l'outil, tout est géré en interne.

1. L'Essentiel de la Nouvelle Stratégie

  • 🌐 Une Plateforme 100% Web : Lekk Rek est un site web optimisé pour tous les écrans, sans nécessité de télécharger une application mobile pour le moment.
  • 📞 Un numéro de contact unique : Celui du porteur de projet. La plateforme centralise le service client. Les clients ne contactent plus les restaurants directement.
  • 🔒 Centralisation de la gestion : Les restaurants sont des entités "passives" dans le système. Le porteur de projet recrute ses propres prestataires/opérateurs pour gérer les menus et catalogues à leur place.
  • 💳 Paiements multi-options : Le tunnel de commande intègre le paiement via les solutions de Mobile Money (Wave, Orange Money), par Carte Bancaire, ainsi que l'option de Paiement à la livraison (espèces ou transfert à réception).
  • 🚫 Fin du canal WhatsApp : Pour garantir la traçabilité et centraliser les flux, l'option WhatsApp est retirée du périmètre.

2. Cartographie des Espaces (Les 3 Piliers)

La plateforme s'articule autour de 3 interfaces web, avec une séparation stricte des rôles :

💻 1. La Vitrine Publique (Client)

  • Recherche intelligente : Affichage des plats en fonction des demandes et spécifications du client.
  • Tunnel de commande sans friction : Possibilité de commander et payer directement sans aucune obligation de créer un compte (Mode Invité).
  • Dashboard Client (Phase 2) : Espace personnel optionnel.

⚙️ 2. Le Dashboard Administrateur (Porteur de Projet)

  • Gestion du parc de Restaurants : Création et mise à jour des fiches restaurants (qui n'ont aucun accès).
  • Gestion des Opérateurs : Création des accès pour les agents de saisie.
  • Supervision centrale & Finance : Vue globale sur les commandes et paiements Mobile Money.

👨‍💻 3. Le Dashboard Opérateur (Prestataires)

  • Gestion des catalogues déléguée : Renseignement quotidien des plats, prix et disponibilités pour le compte des restaurants.
  • Suivi opérationnel : Visualisation des commandes payées en cours (Kanban).

3. Le Parcours de Commande & Paiement

🛵 Option 1 : Se faire livrer 🥡 Option 2 : À emporter
1. Sélection "Livraison". 1. Sélection "À emporter".
2. Saisie simple des coordonnées de livraison (sans création de compte). 2. Saisie des coordonnées de contact (nom, téléphone) sans compte.
3. Paiement : Sélection du mode de paiement (En ligne sécurisé ou à la livraison). 3. Paiement : Sélection du mode de paiement (En ligne sécurisé ou à la livraison).
4. Transmission aux opérateurs Lekk Rek et suivi de livraison. 4. Suivi du statut de préparation par les opérateurs.
💡 Exigence métier : Chaque étape de la commande est tracée, horodatée et conservée dans l'historique d'audit.

4. Règles Métier et Fraîcheur des Données

  • Gestion des statuts : Toute offre est rattachée à une date, un créneau et un statut (Disponible, Épuisée).
  • Obsolescence : La bascule de date (midi/soir) est automatique. Une offre hors date n'apparaît jamais.

5. Exigences Techniques, Performances et Sécurité

Architecture imposée : Plateforme Web React (SPA) → API REST Spring Boot → MySQL.

  • Responsive Design (Mobile First) : Adapté aux smartphones sans téléchargement d'application.
  • Performances : Page publique affichée en moins de 3s (3G).
  • Sécurité : Mots de passe hachés, jetons d'authentification, webhooks de paiement sécurisés.
  • Données Personnelles : Purge automatique des données nominatives (Loi 2008-12 CDP).

6. Planning & Livrables

  • Charge estimée : 7 à 9 semaines pour 2 à 3 personnes.
  • Livrables attendus :
    • Code source (React et Spring Boot).
    • Schéma MySQL versionné.
    • Tests automatisés et Procès-verbal de recette.

7. Critères d'Acceptation (MVP)

🎯 7.1 Critères Fonctionnels

  • [ ] Paiement multi-options : Règlement réussi via Mobile Money, Carte Bancaire, ou sélection de Paiement à la livraison.
  • [ ] Recherche tolérante : Chercher "tiep" retourne la thiéboudienne.
  • [ ] Commande "Invité" : Commander sans jamais créer de compte.
  • [ ] Fraîcheur : Disparition automatique des offres obsolètes.

🛠️ 7.2 Critères Techniques et Exploitation

  • [ ] Expérience Mobile : Affichage Mobile-First parfait sans forcer la PWA.
  • [ ] Sécurité Financière : Webhooks de paiement inviolables.
  • [ ] Auditabilité : Traçabilité de toute modification.
  • [ ] Hygiène du code : Aucun secret (clé d'API) dans le Git.
